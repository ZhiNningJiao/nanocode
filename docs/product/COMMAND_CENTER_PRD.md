# Nanocode 指挥舱（Command Center）产品定义

> 状态：草稿 v0.1（2026-11-21）。只是产品定义，不含代码。
> 调研依据：[COMMAND_CENTER_RESEARCH.md](./COMMAND_CENTER_RESEARCH.md)。正文里的 `〔M 13/27〕` 表示
> 「功能 M 在 27 个高星项目里出现 13 次」；`〔负责人〕` 表示来自产品负责人的原话或批注。

## 0. 一句话

**指挥舱 = Nanocode 里一块「按人能理解的大事件」组织的看板：大事件来自任务系统，派出去的智能体（下称「车」）折叠在大事件下面，
一眼看出哪件事进行到哪、哪辆车在等人、额度还剩多少；对话、探活、容灾、插件都是可开关的模块。**

它比 Langfuse 这类可观测平台轻得多：不要 SDK 埋点，不要单独的数据库，只读现成的日志、状态文件和 HTTP 接口。

## 1. 用户与定位

| 项 | 说明 |
|---|---|
| 主用户 | 同时指挥十几辆车的一个人（产品负责人）。主要在电脑上看，常在手机上看，以后可能在眼镜上看。 |
| 次用户 | 主控智能体（负责派车、收车、汇报的那个常驻会话）和同步脚本：它们读指挥舱的快照接口，也通过它写回任务系统。 |
| 使用频率〔负责人〕 | 最常用：①和主控智能体对话；②看剩余额度。其次：③看大事件进展（甘特 / 节点图）。偶尔：车的实时细节、插件、设置。 |
| 不是什么 | 不是项目管理软件（不做自定义字段、工时）；不是 trace 平台（不做 span 树、评测）；不替代外部 IM。 |

已经定下的方向〔负责人〕：

1. 选「指挥舱」方向（第二轮三个原型：泳道甘特 / 节点图 / 左列表右详情，都按这个方向）。
2. 甘特图和节点图按「人能理解的大事件」排，车折叠在大事件下面，看得出何时开始、进行到哪。
3. 对话不单独占主布局，做成一个功能（抽屉 / 浮窗）。和 IM 重叠，但还是要做。
4. 要比 Langfuse 更轻的监控，放进 Nanocode。
5. 以后可能上眼镜。
6. 设置里能开关模块。
7. **大事件要和任务系统的单硬连接**：车跑的时候，看板上就能直接看到单的状态（§5）。

## 2. 核心场景

| # | 场景 | 用户动作 | 指挥舱要给的 |
|---|---|---|---|
| S1 | 早上 / 回到电脑前 | 打开 Nanocode | 首屏：今天几件大事件，各自进度、预计完成时间；顶部「等你 N 件」；最紧的额度池。10 秒内看懂。 |
| S2 | 有车在等人拍板 | 点「等你」徽章 | 列出所有等人的车：哪件大事件、卡在什么问题、给了哪几个选项、等了多久；可直接打开对话抽屉回复主控智能体。 |
| S3 | 想知道某件事进行到哪 | 点开一个大事件 | 展开里程碑 + 挂在下面的车（开始时间、当前里程碑、最近一条进度、预计完成）；能跳到任务系统里那张单。 |
| S4 | 派车前看额度 | 看额度模块 | 每个额度池的 5 小时 / 7 天用量、重置时间、是否登录、数字来源（官方 / 估算）。 |
| S5 | 和主控智能体说话 | 点浮动按钮 | 抽屉里对话，不离开看板；看板上的事件 / 车可以「引用」进对话。 |
| S6 | 出了故障 | 看到红点 / 收到提醒 | 服务探活变红、额度见底、车超时、容灾检查失败——各自在模块里露出，并按规则推送。 |
| S7 | 手机上瞄一眼 | 手机竖屏打开 | 同样的大事件列表（单列），「等你」和额度放最上面。 |
| S8（以后） | 眼镜上瞄一眼 | 抬眼 | 一行摘要：「4 件事 · 1 件等你 · 最低额度池 12% · 服务全绿」。 |

## 5. 事件 ↔ 任务系统硬连接（P0-3 详细定义）

> 修订（负责人第二轮意见）：任务系统上的单**同事也会看**，所以单上只写**给人看的精炼进展**；车的流水日志（派出、里程碑、卡住、交付、收车……）全部留在**本地时间线**，看板和甘特图从本地读。本节取代 §4 P0-3 与 §10 M1 里「里程碑摘要写成单评论 / 里程碑出现在单评论里」的旧说法。

### 5.1 原则

1. **任务系统是大事件的唯一来源。** 看板不自己存一份「大事件」，只读任务系统；看板上看到的事件状态 = 单的状态。
2. **没有单号不许派车。** 派车入口（主控智能体 / 派车脚本）在派车前校验单号存在且没关；校验失败直接拒绝派车，并说明原因。
3. **车不直接写任务系统。** 只有同步器（一个独立的同步进程，或主控智能体调用的同步脚本）能写；车只在本地写状态和里程碑。
   这样写入方只有一个，好限流、好去重、好审计，凭据也不用发给每辆车。
4. **单上只写精炼进展，日志留本地。** 单上写两样东西：单的状态，以及「这件事进展到哪」的 1–3 句大白话（结果是什么、还差什么、大概什么时候有结论）。
   不出现车名 / 车编号、额度池、模型名、文件路径、内网地址、提交号，也不贴日志。只在这件事**真有进展**时写，同一张单**每天最多 1 条**；没有进展就不写。
5. **先进待发队列，人放行再发。** 同步器起草的每一条（状态变化 + 评论）先落到本地待发队列，主控智能体或负责人看过、放行后才发到任务系统。等写法稳定后，可按事件类型逐步改成自动放行（配置项，默认人放行）。

### 5.2 对象关系

```
任务系统
└─ 总单（可选，如「本周交付」）
   └─ 事件单  ←→  看板上的「大事件」（1:1）
        ├─ 单的状态、负责人、截止日期、标签 —— 只读，用于展示
        ├─ 进展评论（每天最多 1 条，经待发队列放行）
        └─ 车 a-01、车 a-02 …（N:1，每辆车必须挂且只挂一张事件单）
             └─ 车的全部事件 —— 只在本地时间线（按 trace 编号存），不上任务系统
```

- 大事件可以是一张独立单，也可以是一张总单下面的分类单（子单）。用哪一层当「事件」由配置决定（例：「带某个标签的单」或「某张总单的直接子单」）。
- 一辆车只挂一个事件单。一件事要拆多辆车，就多辆车挂同一张单；要拆成多件事，就在任务系统里开多张单。
- 每辆车一个 **trace 编号**（= 车编号；同一辆车续跑另起编号并指向上一个），本地时间线、甘特图、车的会话记录都按它串起来，人和智能体都按它追踪（见 §5.10）。

### 5.3 状态映射（车 → 单）

车的状态用统一词表（§6.3）。同步器按下表推单的状态；单的具体状态名（如 `In Progress`）由配置给出，下表用通用名。所有车事件都写本地时间线；「进展评论」一列说明它会不会触发单上的评论。

| 车的事件 | 本地时间线 | 进展评论 | 单状态（通用名） |
|---|---|---|---|
| 派出（单上第一辆车） | 记 | 不触发 | 待办 → 进行中 |
| 派出（单已在进行中） | 记 | 不触发 | 不变 |
| 里程碑 | 记 | 不触发 | 不变 |
| 等人拍板 / 被卡住 | 记 | **触发**（写清要负责人定什么） | 不变；加「等人」标签 |
| 交付待验（车交了，还没人验） | 记 | 不触发（等验收） | 下面所有车都交付 / 收车 → 待验收 |
| 验收通过、收车 | 记 | **触发**（这件事的结果、还差什么） | **这张单下所有车都收了**才推下一状态 |
| 验收打回 | 记 | 触发（结论变了） | 退回进行中 |
| 车失败 / 超时 | 记 | 不触发 | 不变；加「需处理」标签 |

规则：
- 单的状态只往「更靠后」推，除非是验收打回；同步器绝不把一张已「完成」的单自动改回去。
- 单从「待验收」进「完成」默认要人确认（看板或任务系统里点），可配置为全部车收完后自动推。
- 状态变化和评论一样走待发队列（§5.11）。

### 5.4 同步方向与频率

| 方向 | 内容 | 频率 | 说明 |
|---|---|---|---|
| 任务系统 → 看板 | 事件单列表、状态、标题、截止日期、标签、最近评论 | 轮询，默认 60 秒；支持 webhook 时改为推送 + 每 10 分钟兜底全量对账 | 读 |
| 车 → 本地时间线 | 车的全部事件 | 事件触发（车写本地状态文件 / 派车服务事件），同步器每 15 秒到 5 分钟扫一次 | 本地，不出网 |
| 同步器 → 待发队列 | 状态推进、标签、进展评论草稿 | 有真进展或状态该变时起草 | 本地 |
| 待发队列 → 任务系统 | 已放行的条目 | 放行后发 | 写 |

### 5.5 限流与去重

- **每天一条**：同一张单每天最多 1 条进展评论（按负责人所在时区算「天」）。今天已发、或已放行待发的评论都占额；超出的进展顺延到第二天，不丢。
- **合并**：当天还没放行的草稿遇到新进展时，并进来重写成一条（旧稿作废留档），不新增第二条。
- **写队列**：全局默认每分钟最多 30 次写；超出就排队，不丢。
- **幂等**：每条进展带「车事件编号」生成的去重键；同步器重启后重放不会重复起草或重复发（本地记账；发之前核对已发记录）。
- 任务系统返回限流（如 HTTP 429）时，按它给的重试时间退避；连续失败超过阈值，看板该事件显示「同步滞后」，并进「等你」队列。

### 5.6 冲突处理

| 冲突 | 处理 |
|---|---|
| 人在任务系统里改了单的状态，和同步器想推的不一致 | **人优先**。发出时才比较：只在「单当前状态 = 起草时看到的状态」时才推（比较后再写）；不一致就不改状态，评论照发，并在看板上标「状态被人改过」。 |
| 两个同步器同时跑 | 同一时刻只允许一个同步器持有写锁（租约）；拿不到锁的只读。 |
| 车挂的单号不存在 / 打错 | 派车前校验就会拒绝；如果派车后单被删，按下面「单被关了」处理。 |
| 看板和单对不上（漏同步） | 每 10 分钟全量对账：以任务系统为准，修正看板；本地时间线比单更新时，按 §5.3 补起草。 |

### 5.7 单被关了，车怎么办

参考 symphony 的「每轮对账，单进终态就停运行」，但更保守：

1. 同步器发现单进了终态（完成 / 取消 / 删除），而下面还有车在跑：**不自动停车**。
2. 把这些车标成「单已关」，放进「等你」队列，告诉主控智能体和负责人：「单 X 已关，车 a-01 还在跑，要停、改挂另一张单，还是跑完？」
3. 车跑完的结果照常记在本地时间线；单若已关，最多起草一条进展评论，不改单状态。
4. 可配置为「单被取消 → 自动通知主控智能体停车」，默认关。

### 5.8 看板展示

- 事件卡片：单号（链接到任务系统）+ 单状态徽章 + 标题 + 最近一条里程碑（时间 + 一句话，**读本地时间线**）+ 车数 + 「等你」标记 + 同步状态（正常 / 滞后 / 失败 / 待放行 N 条）。
- 点开事件：先看单的信息（状态、截止日期、负责人、最近一条进展评论），再看下面的车列表；每辆车可再展开本地时间线里的全部事件。
- 「未归类」组：没挂单或单号无效的车（理论上派车校验会拦住，这里是兜底的可见性）。
- 待发队列入口：列出待放行的条目（单号、要改的状态、评论原文），可在这里放行 / 改字 / 丢弃。

### 5.9 接口（通用，任务系统无关）

同步器面向一个任务系统适配器，适配器只需要实现：

```
listEvents(filter) -> [{ id, key, title, state, dueAt, labels[], url, updatedAt }]
getEvent(id)       -> { ...同上, recentComments[] }
transition(id, fromState, toState) -> ok | conflict   // 比较后再写
comment(id, body, dedupeKey)       -> ok | duplicate
addLabel(id, label) / removeLabel(id, label)
```

接第二种任务系统 = 新写一个适配器文件 + 在配置里登记一行。

### 5.10 本地时间线（车的日志放这里）

- 按单分文件，每行一个车事件，追加写、按事件编号去重。字段：

| 字段 | 说明 |
|---|---|
| `trace_id` | 车的 trace 编号（= 车编号；续跑另起编号） |
| `parent` | 续跑时指向上一个 trace 编号，否则为空 |
| `issue` | 单号 |
| `t` | 事件时刻（带时区） |
| `kind` | `dispatched` / `milestone` / `waiting_human` / `delivered` / `accepted` / `failed` |
| `label` | 一句话（本地细节，可含模型、额度池等；不上任务系统） |

- 甘特图（P1-1）一根条 = 一个 trace：起 = 派出，止 = 收车 / 失败，点 = 里程碑，所属泳道 = 单号。车的会话记录也按 trace 编号挂上，用于回看「这件事以前怎么试过」。
- 单级事件（草稿入队、已发）另记一份队列日志，不混进车的 trace。

### 5.11 进展评论与待发队列

- **触发**：该单下有车被验收收下（含「有结果给负责人看了」）、有事要负责人定、结论变了（验收打回）。派出、里程碑、交付未验、失败只记本地。
- **写法**：按固定模板，从车交付报告里的「大白话」段起草 1–3 句；可以用自建模型起草。草稿必须过一道**过滤**：出现车编号、额度池、模型名、路径、内网地址、提交号的一律打回重写；重写还不过就丢弃（原稿留档给人看）。
- **退回规则版**：模型调不通时，只起草状态变化、不写评论；进展留到下一轮再起草。
- **队列**：草稿落在 `pending/`；人把它挪到 `approved/` 才会被发（发之前再过一遍过滤，人改过的字也拦）；发完进 `sent/`，被拦的进 `rejected/`，被新稿合并掉的旧稿进 `superseded/`。
- **发送**：默认空跑；要同时打开两道开关才真发。发出时按 §5.6 比较后再写，并再次检查「今天这张单是否已发过评论」。

## 6. 信息架构

### 6.1 页面结构

```
指挥舱
├─ 顶栏：最紧的额度池 · 「等你 N」徽章 · 服务异常数 · 同步状态 · 设置
├─ 主区（视图可切：列表〔P0〕/ 泳道甘特〔P1〕/ 节点图〔P1〕）
│   ├─ 大事件 E1（= 任务单）：单状态 · 进度 · 预计完成 · 等你? · 车数 · 最近里程碑
│   │    ├─ 事件里程碑
│   │    └─ 车 a-01：状态 · 开始 · 当前里程碑 · 最近进度 · 预计完成 · 额度池 · 模型
│   │         └─ 车的里程碑 / 转录尾巴〔P1〕/ 产物与 PR 链接
│   ├─ 大事件 E2 …（全绿且无人等待时默认折叠）
│   └─ 未归类（没挂单的车）
├─ 侧栏模块（每个都能在设置里关）：额度 · 服务探活〔P1〕· 容灾〔P1〕· 插件〔P1〕· 运行监控〔P1〕
├─ 对话抽屉（右下浮动按钮）
└─ 设置：模块开关 · 插件开关 · 数据源配置 · 任务系统映射 · 提醒阈值 · 布局（桌面 / 手机 / 眼镜）
```

### 6.2 大事件的进度与预计完成

- 进度：事件里程碑按「完成 / 进行中 / 未开始」加权；事件没定义里程碑时，用下面车的完成比例，并标注「按车数估算」。
- 预计完成：优先用单上的截止日期；没有就取下面车里最晚的预计完成，并标注「推算」。
- 「等你」：下面任一辆车处于 `waiting_human` 或 `blocked`，或单「已关但车在跑」，或「同步滞后」。

### 6.3 统一状态词表（全产品只此一份）

车：`queued` 排队 · `running` 跑中 · `waiting_human` 等人 · `blocked` 卡住 · `delivered` 交付待验 · `done` 已收车 · `failed` 失败 · `timeout` 超时 · `unknown` 未知。

`unknown` 只在数据源确实没给状态时出现，界面上明确显示「未知」，不猜成「跑中」。

## 7. 数据从哪来（通用接口）

每类数据一个适配器，适配器用 Nanocode 现有插件清单（manifest）登记；加一个来源 = 加一个适配器文件 + 登记一行。

| 数据 | 通用接口 | 典型实现 | 刷新 |
|---|---|---|---|
| 事件来源 | §5.9 任务系统适配器 | 任务系统 API（如 Linear、GitHub Issues、Jira） | 60 秒 / webhook |
| 车状态来源 | `listRuns(window) -> [{ id, eventKey, state, agent, model, pool, startedAt, endedAt, eta, lastProgress, milestones[], workspace, prUrl }]` | ①派车服务的 HTTP 接口；②约定目录下的状态 / 信号文件（完成 / 等人 / 失败 三类标记文件 + 每车一份里程碑文件）；③编码智能体本地会话日志 | 10–15 秒 |
| 额度来源 | `listPools() -> [{ id, provider, windows: [{ span: "5h"|"7d", usedPct, resetAt }], loggedIn, provenance: "official"|"estimate"|"unknown", checkedAt }]` | ①智能体 CLI 自己上报的官方额度（如状态栏数据）；②本地日志估算（ccusage 的做法）；③网关的花费响应头 | 60 秒 |
| 探活来源 | `listProbes() -> [{ name, target, kind: "http"|"tcp", status: "up"|"down", latencyMs, checkedAt, history[] }]` | Nanocode 现有服务探活配置与接口 | 30 秒 |
| 运行监控来源 | `runMetrics(runId) -> { turns, toolCalls, elapsedSec, tokensIn, tokensOut, costEstimate, provenance }` | 派车服务接口或本地会话日志 | 30 秒 |
| 对话 | 复用 Nanocode 现有智能体会话 | — | 实时 |
| 容灾来源 | `listDrChecks() -> [{ id, kind, lastRunAt, lastResult, ageSec, detailUrl }]` | 见 §9 | 5 分钟 |

公共约定：
- 每个返回都带 `checkedAt` 和来源可达性；来源挂了返回「不可达」，不抛错、不返回空列表冒充「没有数据」。
- 所有地址、凭据走 Nanocode 个人配置，不写死在代码里；凭据只在服务端，前端拿不到。
- 只读。唯一会写外部系统的是 §5 的同步器。

## 8. 不做什么

1. 不做 trace / span 树、评测、提示词管理、数据集（Langfuse / phoenix / opik 那一套）。
2. 不做通用项目管理：不加自定义字段、工时、导入导出；任务的增删改在任务系统里做。
3. 不做 diff 审阅、合并 PR；界面上没有合并 / 批准按钮，只有链接。
4. 不做公开状态页。
5. 不替代 IM；对话抽屉只是入口。
6. 不在界面里直接杀进程、改别人的会话；需要操作时（P2）走主控智能体或派车服务接口，二次确认。
7. 不靠猜：车属于哪件事靠派车时显式挂的单号；额度数字标来源；不认识的状态显示「未知」。
8. 不加新的常驻数据库；历史数据保存在 Nanocode 现有的数据目录里（原子写），默认保留 30 天。

## 9. 容灾面板（P1-6）

> **待补**：容灾模块的具体设计由另一份文档负责（整理现有容灾 / 值守脚本，计划一并收进 Nanocode）。写本稿时那份设计还没出，
> 下面只写指挥舱这一侧的通用要求；设计出来后按它补表格里的具体检查项。

通用要求：

1. **只读展示，每项一行**：检查项名 · 上次运行时间 · 上次结果（通过 / 失败 / 没跑）· 距今多久 · 详情链接。
2. **覆盖面**：
   - 备份：关键数据（会话元数据、终端回放、设置、任务映射）最近一次备份是什么时候、能不能读回来；
   - 主备切换：当前谁是主、备是否可达、上次演练时间和结果；
   - 守护进程：各值守 / 拉起脚本最近一次心跳；
   - 恢复演练：上次从备份恢复的时间和结果。
3. **脚本接入约定**：容灾脚本统一放在 Nanocode 仓库的一个目录里，每个脚本支持 `--status --json`，输出 `{ id, kind, lastRunAt, lastResult, detail }`；
   指挥舱只调 `--status`，不调会改东西的参数。
4. **过期即失败**：某项超过它自己声明的周期 ×2 还没跑，显示「过期」并进提醒。
5. **切换类操作不在界面上做**：主备切换、接管等动作只在文档里给出命令和前置检查，界面不放按钮（以后要放，也必须走 P2-2 的受控操作）。

## 11. 待定问题

1. 「事件」用哪一层单：独立单，还是某张总单的子单？（§5.2，建议两种都支持，配置决定）
2. 单从「待验收」进「完成」默认人工还是自动？（§5.3，建议默认人工）
3. 单被取消时是否自动通知停车？（§5.7，建议默认不自动）
4. 额度池的「官方」数字从哪拿最稳？（§7，需要逐个智能体 CLI 核实）
5. 眼镜的目标设备和显示能力。（P2-1）
6. **指挥舱只读接口谁能读（待负责人定）。** 现状：`GET /api/machines`、`/api/command-center`、`/api/command-center/doc`、`/api/command-center/waiting`、`/api/command-center/quota` 挂在全局 token 检查后面，但全局 token **默认为空 = 不检查**，所以局域网里能连到服务端口的人都能读（机器名 / 负载、任务单标题、车的报告全文、等你队列、各池额度）。会话类接口（`/api/sessions…`）另外叠了「只认本机」，这几条没有。两种做法：
   - **A. 只认本机**：和会话接口一样加本机判断。最严；代价是从外部地址（手机、另一台电脑）看不到这些面板，除非走本机转发。另外「只认本机」靠的是「前面没有反向代理」这个部署前提，以后加了反代要在反代上复刻限制。
   - **B. 跟随全局 token**：保持现在的挂法，但在部署清单里要求设置非空 token（或者 token 为空时这几条接口单独拒绝 / 告警）。负责人在外部地址看面板的用法不受影响，只需要浏览器里带 token。
   - 第二期**没有改默认行为**（负责人正在用外部地址看这些面板）。选哪种、什么时候切，由负责人定。

## 12. 第二期落地记录（等你 / 额度 / 对话抽屉）

- 三个都是插件，设置 → 插件里逐个开关（关掉立刻从界面消失，刷新后保持）：
  - **等你**（`cc-waiting`）：右栏标签 + 顶栏「等你 N」徽章。数据契约见 [COMMAND_CENTER_CONTRACTS.md](COMMAND_CENTER_CONTRACTS.md) §1–2。
  - **额度**（`cc-quota`）：右栏标签 + 顶栏「最紧」徽章（最紧的 1–2 个池）。只读本地缓存的官方响应头读数，不为面板调模型接口；超过 15 分钟没更新标「旧」，过了重置时间的窗口作废。契约见 §3。
  - **对话抽屉**（`cc-chat`）：右下角浮动按钮，接到当值主控**现有的**智能体会话标签（不新开会话）；标签不存在 / 不是块模式就明说，不猜。
- 每块数据独立降级：来源挂了只那块显示「来源不可达 + 最后成功时间」；「等你拍板」清单文件不存在显示「未接入」，不显示成「没有待批」。
- 链接只放行 `http:` / `https:`（服务端映射丢弃、前端再兜一层显示成纯文字），任务单、PR、看板、拍板清单的链接都走同一个过滤函数。
